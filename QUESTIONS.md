# Ответы на контрольные вопросы

1. **Зачем добавлять PHP в PATH и как проверить установку?** PATH позволяет запускать php из любой папки без полного пути к php.exe. Команды `php -v` и `php --ini` показывают версию и используемый файл настроек.
2. **Как запускается встроенный сервер и как изменить порт или корневую папку?** Из каталога проекта: `php -S localhost:8000`. Другой порт можно указать, например, `localhost:8080`. Корневой каталог задаётся параметром `-t`.
3. **Почему форма требует enctype="multipart/form-data"?** Этот тип кодирования передаёт содержимое файла. Без него файл не попадёт в `$_FILES`.
4. **Какие ключи есть в $_FILES['userfile'] и что такое tmp_name?** `name` — имя; `type` — MIME-тип; `tmp_name` — временный путь; `error` — код результата; `size` — размер в байтах. Временный файл нужно переместить до завершения скрипта.
5. **Чем move_uploaded_file() отличается от copy()?** `move_uploaded_file()` предназначена для HTTP-загрузок и проверяет, что источник является загруженным файлом. `copy()` просто копирует файл.
6. **Чем отличаются upload_max_filesize и post_max_size?** Первая ограничивает один файл, вторая — весь POST-запрос. `post_max_size` должна быть больше.
7. **Что будет при превышении post_max_size?** PHP оставит `$_POST` и `$_FILES` пустыми; это нужно отдельно проверять по длине запроса.
8. **Почему upload_max_filesize нельзя изменить через ini_set()?** Лимит применяется до запуска скрипта. Его задают в `php.ini` или параметрами запуска PHP.
9. **Для чего используют basename()?** Она отбрасывает части пути и оставляет имя файла, помогая не допустить выхода за пределы папки. Нужны и дополнительные проверки.
10. **Почему нельзя разрешать загрузку .php?** Такой файл может выполниться на сервере через браузер. Скриптовые расширения запрещают, чтобы не допустить выполнения вредоносного кода.
